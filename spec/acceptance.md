**How the `sh` blocks run.** Each check runs the commit under test, never `main`, and needs no credentials or network beyond the install in S1-3.

- **CI's checkout.** The `readme` job checks out the commit under test with `actions/checkout`, `fetch-depth: 0` (so `origin/main` exists) and `persist-credentials: false`, as the gate's `generic` job does.
- **One script.** The whole block is extracted from `README.md` and run as one script with `sh -e`, so a `cd` carries over to the lines after it, and the first failing line fails the check.
- **The clone line (S1-3).** The script runs in a new empty directory. Git is configured for that run only (`GIT_CONFIG_COUNT`, or `git config --global` in the job) with `url.<path of CI's checkout>.insteadOf https://github.com/aray4702/local_meeting_transcriber.git`. So the README's clone line, unchanged, clones CI's checkout, whose `HEAD` is the commit under test. The `HEAD` comparison in S1-3 confirms this. If it doesn't hold, the check fails rather than testing another commit.
- **The install (S1-3).** The install downloads the locked packages from the package indexes the lock file names. It doesn't download models: `lmt --help` needs none.

**Where CI runs it.** The `readme` job in `.github/workflows/product.yml` runs the CI checks of S1-1 to S1-5. The gate fails any change that breaks them, so the README stays true. The job's details are the Developer's, within this table.

## G1: offline speaker-labelled transcription, and a reproducible evaluation

**Goal:** `project_requirements.md` §2, G1. **Measurable outcome:** "F1–F5, F9; Q1–Q4, Q7, Q8 met on the named evaluation sets; the README's results table regenerated by one command (F4)." **Deadline:** 2026-10-30 for the checks CI runs; 2026-10-31 for the checks on the Owner's Mac, the readings by eye (G1-4m, G1-13) included, in requirements v1.10 (#84, answer 1).

The names below (`lmt`, its options, exit codes, the transcript schema, file paths) are the ones `design/public-api.md` and `design/architecture.md` propose. If the Owner picks other options on #81, this section follows.

### Terms

- **The product run:** `lmt transcribe <input>` with default options, so with the default engine, Kyutai STT 1B (F11, G4), and with the default models already downloaded and verified (`lmt models download`). No speaker count is given.
- **Word error rate (WER):** the reference and the hypothesis both go through the English text normalizer (`EnglishTextNormalizer`, the copy the harness vendors from openai-whisper's repository at a pinned commit; only the normalizer's code, no model). Then `jiwer` scores the whole set at once: total substitutions, deletions and insertions over total reference words, not a mean of per-file rates.
  - **LibriSpeech:** each utterance is transcribed on its own, with diarization off (`--no-diarize`), as one file.
  - **AMI:** each meeting is transcribed whole, by the product run. The reference is every word of every speaker in the AMI manual annotations (v1.6.2), sorted by start time. The hypothesis is the transcript's words in order. Speaker labels don't count towards WER (#81, question 3).
- **Diarization error rate (DER):** `pyannote.metrics` `DiarizationErrorRate`, with `collar=0.0` and `skip_overlap=False`, scored over the whole set. The hypothesis is the exported transcript: each JSON segment's `start`, `end` and `speaker` (#81, question 4). The reference is the `only_words` RTTM files of the AMI diarization setup (`BUTSpeechFIT/AMI-diarization-setup`, at the commit the dataset manifest pins). The scored region is the whole file, so there is no UEM.
- **Real-time factor (RTF):** the product run's wall-clock time, from process start to exit, over the audio's duration. It includes model loading and excludes model download. Over a set, it is total time over total duration.
- **Evaluation sets** (each pinned by a manifest that lists every file's URL and SHA-256):
  - **LS full:** LibriSpeech test-clean, all 2,620 utterances.
  - **AMI full:** the Mix-Headset recordings of the 16 meetings in AMI's standard Full-corpus-ASR test split: EN2002a–d, ES2004a–d, IS1009a–d, TS3003a–d.
  - **CI subset**, which CI downloads and caches:
    - **LS-ci:** 20 fixed LibriSpeech test-clean utterances, about 2.5 minutes. Their IDs are listed in the manifest.
    - **AMI-ci:** the first 300 s of ES2004a's Mix-Headset recording. Its references are cropped to the same span.
    - Together that is about 7.5 minutes of audio, sized so that G1-5's double run fits in a CI job of about 20 minutes. If the first measurement says otherwise, the Architect resizes it in this section.
- **The one-hour recording:** AMI full's meetings in the order listed above, concatenated and cut at 3,600 s. Its references are cropped to match. A manifest recipe builds it.
- **The reference clip:** `tests/fixtures/clip.wav`, about 60 s of LibriSpeech test-clean speech from one speaker. A recipe in the repository builds it from the pinned source utterances, along with its encodings: FLAC; MP3 at 128 kbit/s; M4A (AAC-LC) at 128 kbit/s; and MP4 and MOV files with an AAC track and a still video track.
- **The two-speaker clip:** `tests/fixtures/two_speakers.wav`, about 60 s. A recipe builds it from LibriSpeech test-clean utterances: four alternating turns by one female and one male speaker, with 0.5 s gaps. Its RTTM and word references come with it.
- **Results file:** `results/<set>.json`, which `lmt eval` writes. It holds the figures for each set and system, the commit, the model revisions, the machine (`uname -m`, CPU model, memory) and the date. `public-api.md` describes the format.

## G2: live transcription

G2 builds on G1's pipeline and public API. The names below (`lmt live`, its options, the event stream, `results/live.json`) are the ones `design/public-api.md` and `design/architecture.md`, "Live mode (G2)", propose.

### Terms

- **The live run:** `lmt live` with default options, with the default models already downloaded and verified. No speaker count is given.
- **The file source:** `lmt live --from-file FILE`. It decodes the file as `lmt transcribe` does, then hands it to the pipeline in blocks at real-time pace, as a microphone would. From the source on, the code path is the microphone's.
- **Lockstep:** a test mode of the file source, reached in process and not from the CLI. It hands over each block only once the streaming stages have finished with the one before. So the stages see what they would see on a machine fast enough to keep up, and the output doesn't depend on the machine's speed. CI's live checks run in lockstep, except where a criterion says real time.
- **Committed word:** a word whose text the live run has written and will never change (G4's "Terms" defines it for each engine: for Kyutai, once its last piece is out). Its speaker label follows in a later event (G4, "words before labels"). Provisional text, such as Apple's volatile results, doesn't count.
- **Matched words:** the reference words that `jiwer`'s alignment marks as hits against the committed words. Both sides are compared after lowercasing and stripping punctuation, without the text normalizer, so that each word keeps its own time.
- **Word delay and label delay (Q10):** G4's "Terms" defines both (#565). The reader is the harness, reading `lmt live --jsonl` through a pipe. Times are measured from the arrival of the stream's `start` event, which marks the start of playback. The speech ends at the matched reference word's end time. Only matched words have a delay. Delays are measured from the end of the word, since a word can't be recognised before it has been said (#82, question 8).
- **Stream delay** (the CI proxy for Q10): in lockstep, how much audio had been handed over when the event that a delay is measured at was written, minus the matched reference word's end time; for words and for labels. It is the delay the streaming method itself adds, with the machine's compute time taken out.
- **p95:** the 95th percentile of the matched words' delays, by the nearest-rank method, pooled over every run in the measurement.
- **The Q10 clip:** AMI-ci (G1's "Terms": the first 300 s of ES2004a's Mix-Headset recording, four speakers). Its reference word times come from the AMI manual annotations (v1.6.2) that G1's harness already pins.
- **Offline word times:** the reference clip and the two-speaker clip have no reference word times. For them, the reference times are the word times of the product run (`lmt transcribe`) on the same clip.

### Terms

- **The engines** (F11): `kyutai`, Kyutai STT 1B (`kyutai/stt-1b-en_fr-mlx`) on the GPU through MLX, the default; and `apple`, the Speech framework's `SpeechTranscriber` on macOS 26 or later, reached through the Swift helper.
- **Piece:** one text token Kyutai emits. It emits at most one per 80 ms step, 0.5 s after its audio (its `audio_delay_seconds`), and never revises one.
- **Word, for Kyutai:** a run of pieces from one that starts a word (SentencePiece's word-start marker) up to the next such piece. Its start is its first piece's step time minus the 0.5 s delay; its end is its last piece's step time plus one step (80 ms), minus the delay. A word is **complete** when the next word's first piece is out, or when 3 steps (0.24 s) without a piece follow it, or at the stop.
- **Committed:** for Kyutai, a piece once it is written, and a word once its last piece is written. For Apple's engine, a word in a final result. Apple's volatile results are provisional and never committed.
- **Word delay** (Q10, "speech to its text"): the time at which the `text` event carrying a matched word's last piece (for Apple's engine, the `text` event carrying the final word) reaches the reader, minus the matched reference word's end time (G2's "Terms"). The reader can't know a piece is a word's last until later; the harness finds it afterwards, from the next piece. This is the definition the spike measured (#565: p95 0.89 s).
- **Label delay** (Q10, "to the text's speaker label"): the time at which the `words` event carrying the matched word, with its speaker, reaches the reader, minus the matched reference word's end time.
- **Apple's version record:** the macOS version and build (`sw_vers`), the locale (`en-US`) and the recognizer's asset status, as the helper reports them. Apple's figures are published with it, since its model can't be pinned (Q7).
- **The Mac:** the Owner's Mac (A1), on macOS 26 or later. **CI:** `macos-26`, as in G1's "Where it runs". Apple's recognizer reports "unsupported" there (A5).

### Terms

- **The app:** `lmt app`, a page served on this computer (`design/public-api.md`). A **session** is `lmt live --jsonl --save-audio` in a process of its own, with the engine chosen on the page and the app's source (`--device` or `--from-file`), so it behaves as on the command line. **Stop** sends it one SIGINT, as Ctrl-C does, so it saves its outputs.
- **The page's stream:** `api/events`, the session's `lmt live` events as server-sent events, in order, then an `end` event with the exit code and whether a transcript was saved.
